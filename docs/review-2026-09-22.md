# Paperless-ngx 3.1 vs. Pipeline: Gegenüberstellung und Code-Review (2026-09-22)

Grundlage: Paperless-Doku zum Tag v3.1.0 (api.md, usage.md, advanced_usage.md,
configuration.md, administration.md, changelog bis 3.2.1), das OpenAPI-Schema der
Live-Instanz, der Quellcode von `documents/bulk_edit.py` und `documents/serialisers.py`
(v3.1.0), sowie Live-Tests mit Wegwerfdokumenten (alle wieder gelöscht).

## 1. Stand der Instanz

| | |
|---|---|
| Version | 3.1.0 (`X-Version`), API-Version 10 (`X-Api-Version`), neuestes Release 3.2.1 |
| Dokumente | einige hundert, alle PDF, Papierkorb mit 30 Tagen Aufbewahrung |

## 2. Was Paperless kann, was die Pipeline selbst baut

| Aufgabe | Pipeline heute | Paperless 3.1 | Bewertung |
|---|---|---|---|
| Datei eines Dokuments ersetzen | Upload neu + Original löschen (`apply`) | `POST /api/documents/{id}/update_version/`: gleiche ID, Metadaten bleiben, alte Datei als Version. Live getestet. | **Umstellen.** IDs bleiben stabil, kein Löschen, Papierkorb bleibt leer, Historie sichtbar. |
| Mehrere Originale zu einem Dokument mergen | lokal `merge_pdfs`, Upload, beide Originale löschen | `POST /api/documents/merge/` (`documents`, `metadata_document_id`, `delete_originals`) erzeugt ein *neues* Dokument. `merge_as_versions` macht Dateiversionen, keinen Seiten-Merge. | Lokaler Merge + `update_version` auf das Hauptdokument + übrige löschen ist besser als beides (ID des Hauptdokuments bleibt). |
| Gebündelten Scan splitten | lokal `split_pdf`/`assemble_pages`, ein Upload pro Teil, Original nach Erfolg aller Teile löschen | `POST /api/documents/edit_pdf/` mit `operations: [{"page": N, "doc": K, "rotate": deg}]`, `delete_original`, `include_metadata`. Löschung erst nach Erfolg aller Teile (Celery chord). | Funktional gleich. Nachteil: liefert nur "OK", die neuen IDs muss man über Tasks suchen; Metadaten pro Teil dann per PATCH. Lokaler Weg bleibt, weil wir die Teile ohnehin lokal lesen und benennen. |
| Seiten drehen | lokal OSD + OCR-Konfidenz-Check | Consumer dreht nur beim OCR-Lauf im Archiv, und OCR wird für Dateien mit Textlayer übersprungen | Lokal bleibt nötig. |
| Leerseiten entfernen | lokal Ink-Threshold | nichts | Lokal bleibt nötig. |
| OCR | lokal ocrmypdf, danach lädt die Pipeline eine Datei *mit* Textlayer hoch | Consumer würde selbst OCRen; wegen Textlayer überspringt er es und erzeugt (auto) auch keine Archivdatei | Konsequenz: die meisten Dokumente haben keine PDF/A. Für Anzeige/Suche egal, `content` ist gefüllt. Wer PDF/A will: `PAPERLESS_ARCHIVE_FILE_GENERATION=always` serverseitig. |
| Unbearbeitete Dokumente finden | alle Dokumente listen, Tags lokal prüfen | `GET /api/documents/?is_in_inbox=true` | **Umstellen**, gleiche Semantik, weniger Traffic. |
| Klassifizierungs-Hinweise | keine | `GET /api/documents/{id}/suggestions/` liefert Klassifikator-Vorschläge (Korrespondent, Tags, Typ, Datum). Live geprüft an einem frisch klassifizierten Dokument: Korrespondent, Tags und Typ passten. | **In den Report aufnehmen** als Hinweis, nicht als Entscheidung. |
| Duplikat-Kandidaten | Volltextsuche mit 10 Stichwörtern | `checksum__iexact=<sha256>` (exakt), `more_like_id` (liefert auf dieser Instanz 0 Treffer, unbrauchbar), `document_fuzzy_match` (Management-Command, nur per Server-Shell), 3.2.0 bringt einen Duplikate-Filter | Checksummen-Filter in `prepare` ergänzen; Stichwort-Heuristik behalten. |
| Datum erkennen | Paperless-Rater ungeprüft im Report, der Agent korrigiert von Hand | `PAPERLESS_IGNORE_DATES` (Env, z.B. Geburtsdatum), `PAPERLESS_DATE_ORDER=DMY` (Default), `suggestions.dates` | Serverseitig `PAPERLESS_IGNORE_DATES=<Geburtsdatum>` setzen. Report-Feld in `created_guess` umbenennen. |
| Bundles schon beim Scannen vermeiden | nichts | Trennblätter mit Barcode (`PAPERLESS_CONSUMER_ENABLE_BARCODES`, PATCH-T), Tag-Barcodes, ASN-Barcodes | Prozessoption für den Nutzer: ein Trennblatt zwischen Dokumente legen, Paperless splittet selbst. |
| Konfiguration ändern | - | `/api/config/` (OCR-Settings, App-Titel) per API/UI; `IGNORE_DATES`, `DELETE_DUPLICATES`, `ARCHIVE_FILE_GENERATION`, Barcodes nur per Env | Env-Änderungen braucht der Nutzer am Server. |
| Volltextsuche | `query` | `query` (Tantivy-Syntax), `text` (Titel+Inhalt), `title_search`. `title_content` ist in API v10 deprecated | Handoff: `title_content` durch `text` ersetzen. |
| API-Version | keine Angabe | `Accept: application/json; version=10`, Header `X-Api-Version` | Pinnen, damit ein Server-Update die Task-/Feldnamen nicht stillschweigend ändert. |
| Workflows / Custom Fields / AI | nicht genutzt | vorhanden | Kein Bedarf für die Pipeline. AI-Vorschläge (Ollama/OpenAI) wären eine serverseitige Alternative zur Klassifizierung durch den Agenten; bewusst nicht gewählt. |
| Papierkorb | Original lokal unter `work/` aufheben | 30 Tage Trash, optional `PAPERLESS_EMPTY_TRASH_DIR` | Mit `update_version` wird kaum noch gelöscht. |

## 3. Code-Review `pipeline/`

### client.py
- Kein `timeout` an den Requests: ein hängender Server blockiert `apply` unbegrenzt. Session-weit Timeout setzen.
- API-Version nicht gepinnt (siehe oben).
- `download_document` Docstring behauptet "original, not the OCR'd archive", die Funktion kann beides.
- `get_task` setzt bei einer als Duplikat abgelehnten Task `related_document` auf die ID des *anderen* Dokuments (aus `related_document_ids`). `_wait_for_task` prüft `FAILURE` vorher, daher ungefährlich, aber ein späterer Aufrufer, der nur `related_document` liest, würde das Duplikat für den Upload halten. Bei `FAILURE` `related_document` auf `None` setzen.
- Kein `update_version`, kein Checksummen-Lookup, kein `suggestions`.

### cli.py
- `fetch` listet alle Dokumente inklusive `content` (1,9 MB Text) und filtert lokal; `is_in_inbox=true` plus `fields=` reicht. Die Zusatzklausel "kein Korrespondent und kein Typ" bleibt als Fallback für Altbestand, sollte aber im Log als solche erscheinen.
- `fetch` wirft die Metadaten weg, `prepare` holt sie pro Dokument erneut (`get_document`). Einmal als `meta.json` neben `original.pdf` speichern, spart Roundtrips und macht `prepare` robust, wenn ein Dokument zwischenzeitlich verschwindet.
- `prepare` schreibt Paperless' geratenes Datum als `created` in den Report. Umbenennen in `created_guess` und `suggestions` (Klassifikator) danebenlegen, damit die Klassifizierung die Hinweise sieht, aber nicht mit dem Ergebnis verwechselt.
- `prepare` Duplikat-Heuristik: SHA-256 des Originals gegen `checksum__iexact` prüfen, exakter Treffer wird als `exact_duplicate_of` gemeldet.
- `apply` Upload+Delete: für Einträge mit genau einer Quelle auf `update_version` umstellen. Der Marker wird `ocr.versioned.pdf`; solche Quellen werden nie gelöscht. Split-Einträge (mehrere Einträge, eine Quelle) bleiben Upload+Delete. Merge-Einträge (eine Entry, mehrere Quellen): `update_version` auf die erste Quelle, übrige löschen.
- Der `sha256`-Vergleich für unveränderte born-digital-Dateien bleibt nötig (identische Bytes als Version hochladen ist sinnlos).
- `_wait_for_task` und `get_task` doppeln sich mit dem Handoff-Client; nach dem Umbau die Handoff-Kopie nachziehen.

### ocr.py
- `extract_markdown` (markitdown) liefert keine Seitenmarker, was den 54-Seiten-Split am 2026-09-22 unnötig schwer gemacht hat. pymupdf ist schon Dependency: `content.md` pro Seite mit `--- Seite N ---` schreiben. Tabellen-Layout bleibt mit `page.get_text("text")` brauchbar; markitdown kann als Vergleichsausgabe bleiben.
- `run_ocr` ohne `rotate_pages` ist korrekt (lokale Rotation läuft vorher), aber `deskew=True` zusammen mit `skip_text=True` deskewt nur Seiten ohne Text. Bewusst, sollte im Kommentar stehen.

### pdf_tools.py
- `analyze_pdf` rendert alle Seiten auf einmal in den Speicher (54 Seiten × 150 DPI ≈ 0,5 GB). Seitenweise rendern.
- `detect_rotation` läuft OSD + zweimal OCR pro Seite. Für born-digital wird es übersprungen, für Scans ist es der Zeitfresser. Akzeptabel, aber nur Seiten mit OSD-Vorschlag ≠ 0 doppelt OCRen ist schon so. OK.
- Blank-Threshold-Falschpositiv (einseitiges Durchschlag-Formular) bleibt dokumentiert, keine Änderung.

### Sonstiges
- `run_ingest.bat` Prompt sagt noch "im Memory-System oder direkt in CLAUDE.md"; CLAUDE.md verbietet inzwischen den Memory-Store für Projektwissen. Prompt anpassen.
- `AGENT_HANDOFF.md`: `title_content` durch `text` ersetzen, `update_version` ist drin, API-Version pinnen.
- `failed_task_ids.json` im Repo-Root ist ein Überbleibsel vom 2026-09-14 (Liste dismissed Task-IDs), nicht referenziert. Löschen.
- Alles seit dem Initial-Commit ist uncommittet (CLAUDE.md +397 Zeilen, cli.py +136). Committen.
- Keine Tests. Der heutige Round-Trip (Upload, PATCH, Dedup, Ersetzen, Version, Löschen) als `python -m pipeline.selftest` festhalten, mit Wegwerfdokumenten, die sich selbst aufräumen.
- Zwei parallele Läufe (`run_ingest.bat` + interaktiv) können sich `work/review/*` überschreiben (dokumentiert). Ein Lockfile in `work/` kostet fünf Zeilen.
